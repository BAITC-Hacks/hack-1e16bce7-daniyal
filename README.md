# Career Quest

Навигатор развития сотрудников для HackAlem AI, трек Halyk Bank.

## Текущее демо

Адаптивный frontend на React + Next.js в стиле Halyk: локальные Manrope и логотип,
единые данные кабинетов сотрудника и HR. Backend остаётся отдельным FastAPI-сервисом.

- `/` — профиль, карьерная цель, до трёх рекомендаций с объяснением, каталог,
  личный план, завершение/отмена в демо, карта навыков и история всех статусов.
- `/hr` — обзор 200 сотрудников, разрывы компетенций, длительные паузы в развитии,
  поиск и фильтры, переход к профилю, CSV-экспорт отфильтрованного списка.
- Вкладка **Данные** — импорт JSON/CSV с проверкой и предпросмотром, добавление
  проверочных профилей жюри, резервная копия и восстановление исходного набора.
- `/hr/insights` перенаправляет во вкладку **Данные**.

Стартовый набор: 200 профилей, 40 мероприятий, 60 навыков, 32 профиля требований
и 2 743 записи истории. Дата сценария фиксирована датасетом: **1 октября 2026**.
Данные синтетические. Прогресс сохраняется в localStorage этого браузера;
кабинеты и открытые вкладки используют один набор. Другой браузер или устройство
имеет своё состояние. Для переноса используйте резервную копию.

Это frontend-прототип: многофакторный скоринг работает локально, LLM, вход,
серверное разграничение ролей и сохранение в БД ещё не подключены. Переключатель
«Сотрудник / HR» и выбор демо-профиля предназначены для демонстрации.
Завершение активности — явно обозначенная симуляция, а не подтверждение обучения.
Текущий frontend не отправляет уведомления в Telegram. Существующий бот использует
свой отдельный mock JSON: [запуск и команды](apps/bot/README.md).

## Запуск только frontend

Node.js 22.13+ ветки 22 LTS или поддерживаемая версия из `apps/web/package.json`.
Docker, API-ключи и backend для этого сценария не нужны.

```sh
npm --prefix apps/web ci
npm --prefix apps/web run dev -- --port 3100
```

Откройте [сотрудника](http://localhost:3100/) или [HR](http://localhost:3100/hr).
После установки зависимостей для запуска нужна только вторая команда.

## Проверить главный сценарий

1. На `/` выберите демо-профиль **E0002 — Arman Zhaksylykov**.
2. Раскройте «Почему это подходит мне» у рекомендации. Объяснение показывает
   разрыв с целью, критичные навыки, историю похожих активностей и нагрузку.
3. Добавьте мероприятие в план. В «Мой план» нажмите «Завершить в демо»
   и подтвердите действие. В «Навыки и история» появятся изменения.
4. Перейдите в HR → «Сотрудники», найдите `E0002`: прогресс уже пересчитан.
5. В HR → «Данные» загрузите JSON профилей и CSV истории в исходной схеме,
   проверьте предпросмотр и примените. По умолчанию записи объединяются по ID.
   Новые профили сразу доступны в обоих кабинетах.

Резервную копию JSON можно загрузить через тот же файловый ввод: она восстанавливает
полный снимок вместо объединения. Для обычных файлов режим «Заменить» заменяет только
выбранные части; ссылки из остальных частей должны остаться валидными.
Файлы читаются в браузере, на сервер не отправляются.

## Методика

База навыков — снимок на `last_review_date`; повторно учитываются только завершения
после этой даты и действия демо. Прирост ограничен `gain`, `max_level` и шкалой 0–5;
уровень, уже превышающий ограничение мероприятия, не уменьшается. Повторное
завершение одной записи отклоняется. Отказы и отсутствие участия не уменьшают навыки.

Рекомендации учитывают цель (или следующий грейд), критичность разрыва, прирост,
историю похожих форматов и навыков, длительность, роль, грейд, предпосылки и даты.
Обязательные мероприятия не входят в рекомендации и не дают игровых баллов.
Покрытие цели — сумма текущих уровней, ограниченных требованием каждого навыка, делённая на сумму требуемых уровней; результат округляется до процента.
Это ориентир развития, а не решение о повышении или рейтинг результативности.

Подробная проверка требований и ограничения: [frontend verification](docs/frontend-verification.md).


## Быстрый запуск

Нужен запущенный Docker Desktop / Docker Engine с Compose:

```sh
cp .env.example .env
docker compose up --build -d --wait
```

В PowerShell вместо `cp` можно использовать `Copy-Item .env.example .env`.

- Приложение сотрудника: http://localhost:3000
- HR Dashboard: http://localhost:3000/hr
- OpenAPI: http://localhost:8000/docs
- API: http://localhost:8000/api/v1/health
- Готовность API + PostgreSQL: http://localhost:8000/api/v1/ready

Ключ OpenAI не нужен. Первый запуск скачивает зависимости и образы.
Web по умолчанию доступен в локальной сети (`WEB_BIND_HOST=0.0.0.0`).
API и PostgreSQL доступны только на localhost; браузер обращается к API через web-прокси.
PostgreSQL использует порт `55432` (`POSTGRES_PORT`) и сохраняет данные в Docker volume.
`docker compose down` останавливает стек без удаления данных.
Локальные credentials из `.env.example` предназначены для разработки.
При изменении credentials обновите также локальный `DATABASE_URL`; для пароля в URL
нужно percent-encoding специальных символов. В уже созданной БД переменные Compose
не меняют пароль автоматически.

## Открыть с телефона

1. Подключите компьютер и телефон к одной Wi-Fi сети.
2. Запустите приложение командой выше. Если `.env` уже существует, убедитесь,
   что `WEB_BIND_HOST=0.0.0.0`, и выполните `docker compose up -d web`.
3. Узнайте локальный IPv4 компьютера (`ipconfig` в Windows, адрес адаптера Wi-Fi).
4. Откройте в браузере телефона `http://<IP-компьютера>:3000`, например `http://192.168.1.10:3000`.
5. Откройте рекомендацию и добавьте мероприятие в план. Установка приложения не требуется.

Если страница не открывается, проверьте доступ к TCP-порту 3000 в брандмауэре
для частной сети и отсутствие изоляции устройств в Wi-Fi.
`localhost` на телефоне означает сам телефон. Для доступа через интернет нужен
отдельный деплой с публичным HTTPS-адресом; текущая настройка рассчитана на локальную сеть.

## Локальная разработка

Нужен Node.js 22.13+ ветки 22 LTS (`nvm install && nvm use` в корне).

```sh
cd apps/web
cp .env.example .env.local
npm ci
npm run dev
```

Сервер слушает `0.0.0.0:3000`: с телефона используйте тот же адрес компьютера.
Сотрудник и HR используют единый frontend-датасет без API; для проверки backend используйте `/api/v1/ready`.
Next.js читает `API_URL` только на сервере и проксирует `/api/v1/health` и `/api/v1/ready`.
Браузеру не нужен отдельный адрес API или настройка CORS.

Для локального backend оставьте PostgreSQL в Docker, остановив контейнеры API/web:

```sh
docker compose stop api web
docker compose up -d --wait db
python3 -m venv .venv
.venv/bin/python -m pip install -r apps/api/requirements-dev.txt
cd apps/api
cp .env.example .env
../../.venv/bin/python -m uvicorn app.main:app --reload --host 127.0.0.1
```

Нужен Python 3.11+. В Windows используйте `.venv\Scripts\python.exe`
вместо `.venv/bin/python` (из `apps/api` — `..\..\.venv\Scripts\python.exe`).

## Миграции

Alembic настроен, но бизнес-таблиц и revisions пока нет.
Из `apps/api` можно проверить подключение: `../../.venv/bin/alembic current`.
Будущие SQLAlchemy-модели регистрируются в `Base.metadata` и импортируются в `migrations/env.py`:

```sh
../../.venv/bin/alembic revision --autogenerate -m "add domain tables"
# Проверить сгенерированный файл перед применением.
../../.venv/bin/alembic upgrade head
```

В Docker: `docker compose exec api alembic upgrade head`.
Миграции применяются явно, а не при каждом старте API.
