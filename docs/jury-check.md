# Сценарий жюри в настоящем браузере

Проверка использует production-сборку Next.js, FastAPI и отдельную PostgreSQL БД.
HTTP-ответы не подменяются. Импорт, вход и завершение выполняются через формы
браузера; дополнительные GET-запросы сверяют фактические значения API.

## Запуск отдельного стенда

Из корня репозитория:

```sh
python scripts/start.py --env-file .env.jury --project cq-jury --web-port 3300 --api-port 8300 --db-port 55433
```

Основной проект и его volumes не изменяются. Откройте http://localhost:3300.
HR-пароль сохранён в `.env.jury`. Повторная команда сохраняет секреты и прогресс.
При ошибке сборки, миграции, импорта или загрузки модели скрипт прекращает запуск
с ненулевым кодом; уже существующие volumes не удаляет.

## Автоматическая браузерная проверка

Нужны Node.js версии из `apps/web/package.json`, Python и установленный Google Chrome:

```sh
cd apps/web
npm ci
npm run test:e2e
```

Вместо установленного Chrome можно выполнить `npx playwright install chromium`
и задать `PLAYWRIGHT_CHANNEL=chromium`. При необходимости задайте `PYTHON=python3`.
`JURY_BASE_URL` и `JURY_ENV_FILE` позволяют выбрать другой **тестовый** стенд;
по умолчанию используются порт 3300 и корневой `.env.jury`.

Тест добавляет синтетический профиль с уникальным ID и копией истории E0001:

1. HR входит и загружает `employees.json` и `activity_history.csv` через `/hr/import`.
2. Сотрудник входит под новым ID, видит профиль, готовность и 1–3 рекомендации.
3. Открывает первую рекомендацию и нажимает «Завершить в демо».
4. Проверяются рост навыков и готовности, обновление рекомендаций, история,
   сохранение прогресса после перезагрузки страницы.
5. HR находит новый профиль и видит ту же готовность и завершённую активность.
6. Проверяются запрет сотруднику читать HR API, отсутствие ошибок JavaScript
   и горизонтального переполнения на ширине 390 px.

Скриншоты desktop/mobile и JSON с изменениями сохраняются в
`apps/web/test-results/` (не входят в Git). Трассировка отключена, чтобы не записывать
пароль HR. Каждый прогон оставляет свой профиль в тестовой БД.
Этот тест проверяет бизнес-сценарий с шаблонными объяснениями; он не подтверждает
доступность GPU или качество/скорость генерации Qwen.

Остановить тестовый стенд, сохранив его данные:

```sh
docker compose --env-file .env.jury --project-name cq-jury stop
```

## Ручное повторение

Создайте два файла для загрузки (новый ID для каждого нового импорта):

```sh
python scripts/create_jury_fixture.py data/jury --id JURY-DEMO-01
```

Войдите как HR, откройте `/hr/import`, выберите «Добавить проверочные профили»
и загрузите оба файла из `data/jury`. Затем войдите как сотрудник `JURY-DEMO-01`
и повторите шаги выше. Будущие сессии завершаются как явно обозначенная демо-симуляция.
