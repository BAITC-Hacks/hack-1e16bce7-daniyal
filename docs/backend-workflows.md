# Backend: каталог, импорт и завершение

Реализовано в дополнение к [демо-входу](backend-auth.md). Все пути имеют префикс
`/api/v1`. Миграция `0002_backend_workflows` добавляет журнал импортов, результаты
идемпотентных завершений и поля демо-симуляции истории. Существующие данные сохраняются.

## API чтения

- `GET /hr/employees` — только HR, полный массив профилей по employee_id.
  Поля: employee_id, full_name, role, grade, tenure_months, department,
  career_readiness. При include_readiness=true вычисляется общим Python-движком;
  без параметра сохранён исходный контракт с null.
- `GET /events` — полный каталог для сотрудника/HR, сортировка event_id.
- `GET /events/{id}` — детали: title, description, type, format, duration_hours,
  mandatory, repeatable, target_roles, target_grades, upcoming_sessions,
  prerequisites (skill_id → level), develops_skills (skill_id, name, gain, max_level).
  Каталог не является персонально отфильтрованной рекомендацией.

## HR-импорт

`POST /datasets/import`, multipart, только HR:

- `mode=initial`: employees.json, events.json, skills.json, activity_history.csv.
- `mode=append`: employees.json и activity_history.csv; только новые сотрудники и
  их история, с уже загруженными навыками/событиями. Руководители могут быть из БД
  или того же пакета. Метаданные должны совпадать с исходным набором.

Форма использует имена файлов как имена полей. Предел — 10 MiB на файл и 42 MiB
на запрос. Ответ: `{status, employees, events, skills, history_records}`;
status — imported/unchanged. Для append events/skills равны 0.

Проверяются поля, связи, даты, уровни и статусы. Ошибки — 422, конфликты ID или
попытка перезаписи — 409, превышение размера — 413. Пакет сохраняется атомарно.
Добавление истории существующим сотрудникам и изменение их оценок пока не поддерживаются.
Повтор того же валидированного пакета возвращает прежние счётчики без восстановления
старого состояния; порядок массивов участвует в fingerprint.

## Завершение в демо

`POST /employees/{employee_id}/activities/{event_id}/complete` — только собственная
сессия сотрудника. HR не может завершать за сотрудника. Обязателен заголовок
`Idempotency-Key` (1–128 символов). Тело JSON:

```json
{"record_id": "R000001"}
```

либо `{"session_date":"2026-10-15"}`, либо `{}` для неповторяемой активности.
record_id и session_date взаимоисключающие. Для повторяемого клуба участие или дата
обязательны. Дата нового участия должна быть из upcoming_sessions; без даты у
неповторяемой активности выбирается ближайшая сессия не раньше среза. Для self-paced
дата сессии не передаётся.

Завершение существующего in_progress/overdue сохраняет источник назначения и исходную
дату. Завершённое участие повторно навыки не начисляет. Неудачная попытка не
переписывается в успешную — создаётся отдельное допустимое участие. Новому участию
проверяются аудитория и prerequisites. Обязательные активности требуют существующего
назначения; выбрать его можно в форме завершения.

Демо разрешает завершить будущую сессию: исходная дата среза — бизнес-«сегодня»,
выбранная дата хранится отдельно в session_date, будущий результат имеет simulated=true.
completed_on хранит дату завершения; исходные записи импорта имеют completed_on=null.
История API отдаёт эти три поля. Навыки меняются через общую apply_skill_effects,
assessed_level и last_review_date не меняются; score/feedback не выдумываются.

Ответ: `{event_id, record_id, already_completed, changes,
career_readiness_before, career_readiness_after}`. В changes — skill_id, name, before,
after. HTTP-обработчик запрашивает readiness до/после внутри транзакции
через существующий движок карьерной готовности. Повтор того же ключа возвращает сохранённый результат с
already_completed=true. Ключ с другим запросом — 409. Новый ключ для уже завершённой
неповторяемой активности/той же сессии не даёт повторного прироста.

Импорт и completion используют общий transaction advisory lock, затем completion
блокирует сотрудника. История, навыки и результат запроса сохраняются одной транзакцией.
В UI ключ сохраняется при повторе запроса; изменение выбранного участия создаёт новый.
Web-прокси передаёт заголовок backend. Будущая активность обозначена как демо-симуляция.

## Подключение и границы

```sh
docker compose up -d --build --wait
docker compose exec api alembic upgrade head
```

Траектория, рекомендации и HR-метрики подключены через career.py; интеграция
описана в [career-workspace.md](career-workspace.md). Интерфейс обращается к API,
а «Раздел в разработке» используется лишь как fallback при 404 ещё отсутствующего
маршрута. Ошибки действующих API остаются видимыми.

Тесты проверяют импорт → вход нового сотрудника → completion → повтор импорта,
конкурентные одинаковые и разные завершения, общий импорт/completion и отсутствие
потери прогресса на PostgreSQL. Новые схемы тестов удаляются после проверки;
основная демо-БД тестами не очищается.
